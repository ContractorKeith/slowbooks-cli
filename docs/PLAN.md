# slowbooks-cli — Build Plan

Status: planned, no code yet (2026-11-09). Grilled 2026-11-09; scope modelled on
basecamp-cli (agent output contract), process on mdkb. Facts from SlowBooks Pro
v2.31.10 and Switchboard (VonHoltenCodes/SlowBooks-Pro-MCP).

## 1. Problem and goal

People and agents who keep their books in SlowBooks Pro have two ways in today: the
browser, and Switchboard's MCP server. Neither suits a shell script, a cron job, or
an agent that already has a terminal. Each MCP tool schema costs context on every
turn, and MCP can't carry a PDF or CSV. SlowBooks Pro ships no CLI.

`sbp` is a single Go binary that talks to a running SlowBooks Pro server over its
token API. It does everyday bookkeeping reads and writes with stable JSON and exit
codes, and reaches any other operation through a generic layer driven by the
server's own `/openapi.json`. It is Keith's project (private repo, MIT), listed in
the SBP plugin directory (`sbp-marketplace`, listing `sbp-cli`). v1 is done when
every **v1** row in §3 works on macOS, Linux and Windows and `scripts/accept.sh`
passes from a clean clone, with `scripts/e2e.sh` green against SlowBooks Pro v2.31.10.

Terms follow `CONTEXT.md`. Decisions that must not be reversed by accident:
`docs/adr/0001-caller-supplied-payment-key.md`, `docs/adr/0002-token-api-client-only.md`.

## 2. User stories

1. As a bookkeeper, I run `sbp auth login`, paste my token once, and every later
   command reaches my server and company without retyping anything.
2. As an agent with a shell, I run `sbp invoices list --open --json --jq '.data[].id'`
   and get only what I need, in a shape documented once.
3. As an agent, I read `sbp --help --agent` or `sbp commands --json` to learn the
   whole command set in one call instead of loading MCP tool schemas.
4. As anyone, when a named command doesn't exist for what I need, `sbp ops find
   "deposit"` then `sbp ops call POST /api/deposits --data @d.json` gets me there.
5. As a bookkeeper, I record a customer's check with `sbp payments record --key
   chk-1042 ...`; if the network drops and I run it again, the payment is booked once.
6. As a bookkeeper, `--dry-run` on any write shows me the exact request and sends nothing.
7. As anyone, `sbp download /api/invoices/42/pdf` saves the PDF under its own filename.
8. As an accountant-role user, a refused write exits 4 with the server's sentence;
   a closed-period write exits 4 with the closing-date message. Neither retries.
9. As an operator with several servers or companies, `--profile` and `--company`
   pick one per call; `sbp doctor` tells me what is wrong with a setup in one screen.
10. As anyone on an older or newer server, `sbp` warns when the server version is
    below 2.31 or outside the versions this build was verified against, and keeps working.
11. As a Switchboard user, I point `SLOWBOOKS_URL` and `SLOWBOOKS_TOKEN_FILE` at the
    same server and token file Switchboard uses, and `sbp` works with no profile at all.
12. As Keith, the plugin directory shows which SlowBooks Pro releases this CLI
    verifies against, from a manifest generated by the CLI itself.

## 4. Architecture

```
cmd/sbp/            main: builds the root command, nothing else
internal/cli/       cobra commands: flags → a request; no HTTP, no file paths
internal/config/    profiles, per-OS paths, token files, precedence
internal/client/    the only HTTP code: network rules, headers, error mapping, retry rule
internal/catalog/   /openapi.json fetch + cache, find/describe, keyed set, file routes
internal/output/    envelope, tables, --jq, --quiet, exit codes; owns stdout and stderr
internal/commands/  named-command table: name → method, path template, flags, next hints
internal/fakeserver/ test-only server (snapshot + fixtures) used by unit tests and accept
cmd/sbp-fake/       runs fakeserver for scripts/accept.sh
testdata/openapi-2.31.10.json   pinned snapshot
testdata/golden/    expected envelopes for accept
scripts/accept.sh   gate + build + goldens + live checks against sbp-fake (< 1 min)
scripts/e2e.sh      real SlowBooks Pro in Docker at the pinned tag (Linux, slow)
scripts/smoke-live.sh  manual reads + invoice create/void on a real server
skills/sbp/SKILL.md user-facing skill (M6)
```

Rules:
- Only `internal/client` makes HTTP requests. Named commands are rows in
  `internal/commands` and go through the same call path as `ops call`.
- Only `internal/output` writes to stdout/stderr and picks the exit code.
- The catalog cache is disposable; deleting it costs one refetch. Token files and
  the profile file are the only state that matters.
- No product code is imported, vendored or copied; the server is reached only
  over HTTP (ADR 0002).

### Dependencies and why

| Module | Why |
|---|---|
| `github.com/spf13/cobra` | command tree, help, completions; walked to emit `--help --agent` |
| `github.com/itchyny/gojq` | `--jq` without an installed jq (Windows, agents) |
| `golang.org/x/term` | hidden token prompt and TTY detection |

Pure Go, `CGO_ENABLED=0`. Tables use `text/tabwriter`. Anything else needs a reason
in the PR body.

## 5. Data and connection model

- **Profile file**: `<config>/profiles.json` `{ "default": "acme", "profiles": {
  "acme": { "url": "...", "company": "...", "token_file": "<config>/tokens/acme.token" } } }`.
- **Config dir**: `$SLOWBOOKS_CONFIG_DIR`, else Linux `$XDG_CONFIG_HOME/sbp` or
  `~/.config/sbp`; macOS `~/Library/Application Support/sbp`; Windows `%APPDATA%\sbp`.
  Never read or write other files already in that folder (Keith keeps Switchboard
  token files in `~/.config/sbp`).
- **Cache dir**: `$SLOWBOOKS_CACHE_DIR`, else the OS user cache dir + `/sbp`.
  Catalog at `<cache>/<profile>/openapi-<server version>.json`.
- **Token file**: one line, `sbp_` prefix, no whitespace. Mode 0600 enforced on
  Linux/macOS (refuse with a `chmod 600` hint otherwise); not checked on Windows.
- **Precedence**: flag > env > profile > default. Env: `SLOWBOOKS_URL`,
  `SLOWBOOKS_TOKEN_FILE`, `SLOWBOOKS_TIMEOUT_SECONDS` (default 120, 1–3600),
  `SLOWBOOKS_COMPANY`, `SLOWBOOKS_PROFILE`. URL + token file from env need no profile.
- **Network rules** (= Switchboard): `https://` required unless the host is
  loopback/private/link-local; certificates always verified; redirects never
  followed; only paths under `/api/` and `/openapi.json`.
- **Headers**: `Authorization: Bearer <token>`; `X-SlowBooks-Company` when a company
  is set; `Idempotency-Key` on keyed operations; `User-Agent: sbp/<version>`.
- **Keyed operations**: `POST /api/payments`, `POST /api/bill-payments`, and their
  `/{id}/discount` routes, plus any operation whose OpenAPI declares an
  `Idempotency-Key` header. A keyed write without `--key` is a usage error (ADR 0001).
- **Role**: no route reports it. Probe like Switchboard: `GET /api/audit?limit=1`
  403 → readonly; else `GET /api/employees` 403 → accountant; else bookkeeper.
  Advisory only; recorded at login, shown by `auth status` and `doctor`.
- **Version**: `GET /api/system` → `version`. Warn on stderr (and in `doctor`)
  when below 2.31 or not in the build's verified list; never refuse.
- **Retry**: reads retry once on network error or 502/503/504. Writes never retry.
  A network error or timeout on an unkeyed write exits 8 with `retryable: false`
  and a hint to check (`sbp invoices list ...`) before running it again.
- **Lists**: most list routes return a bare array. `--limit` (default 50) passes as
  `limit` where the operation takes it (invoices, bills, bank transactions) and trims
  client-side otherwise; `--all` disables trimming. `summary` says `50 of 312 shown;
  --all for everything` when trimmed.
- **Compatibility**: `internal/commands` embeds the list of SBP versions this build
  verified (`testdata/openapi-<v>.json` files). A tag means "verified against these
  versions"; there is no other release process.

## 6. CLI contract

```
sbp version
sbp auth login [--profile P] [--url U] [--company C]   # token: hidden prompt, or stdin when piped
sbp auth status | sbp auth logout [--profile P]
sbp profile list | sbp profile use P
sbp doctor
sbp api <METHOD> <path> [--param k=v]... [--data @file|-|<json>] [--key K]
sbp ops find <words...> | sbp ops describe <METHOD> <path> | sbp ops call <METHOD> <path> [...as api]
sbp search <query>
sbp customers|vendors|items|accounts list [--limit N|--all] | show <id>
sbp invoices|bills list [--status S] [--open] [--limit N|--all] | show <id>
sbp expenses|payments|bill-payments|journal list | show <id>
sbp reports list | sbp reports run <name> [--from D] [--to D] [--param k=v]...
sbp download <path> [-o file|-] [--param k=v]... [--force]
sbp invoices pdf <id> [-o file|-]
sbp invoices create --customer ID --date D [--due D] [--memo M] --data @lines.json [--dry-run]
sbp payments record --key K --customer ID --amount A --date D [--method M] [--apply INV=AMT]... [--dry-run]
sbp bill-payments record --key K --vendor ID --amount A --date D [--apply BILL=AMT]... [--dry-run]
sbp invoices|bills|expenses|journal|payments|bill-payments void <id> [--fee-refunded] [--dry-run]
sbp commands --json | sbp commands --manifest
sbp --help --agent
```

Global flags: `--profile`, `--company`, `--json`, `--quiet`, `--jq <expr>`,
`--timeout <s>`, `--no-color`. Writes add `--dry-run` and `--data`.

**Envelope** (piped, or `--json`): `{"ok": true, "data": ..., "summary": "...",
"next": ["sbp ..."]}`. Errors: `{"ok": false, "error": {"code", "message",
"retryable", "hint", "detail"}}` where `detail` is the server's `detail` verbatim.
`--quiet` prints `data` only. On a TTY without `--json`: a table or key/value view.

| Exit | code | When |
|---|---|---|
| 0 | – | success |
| 1 | `error` | anything else |
| 2 | `usage` | bad flags/args, missing `--key` on a keyed write, network-rule refusal |
| 3 | `auth` | 401, missing/invalid token file, bad permissions |
| 4 | `refused` | 403: role or closing date |
| 5 | `not_found` | 404 |
| 6 | `conflict` | 409, including a reused key with a different body |
| 7 | `invalid` | 422 |
| 8 | `network` / `server` | timeout, connection failure, 5xx (retryable only for reads) |

## 8. Testing

- **Unit** (all three OSes): `httptest` fakes at the `internal/client` seam and the
  command seam (run the cobra root in-process, assert envelope + exit code).
- **Accept** (`scripts/accept.sh`, Linux/macOS, < 1 min): gate (`go test -race ./...`,
  gofmt, vet, staticcheck), build, start `sbp-fake` on a free port, run every v1 command
  against it in a scratch HOME/config/cache, diff envelopes with `testdata/golden/`,
  then live checks for exit codes. Worker, reviewer and CI run this exact script.
- **E2E** (`scripts/e2e.sh`, Linux CI + Omarchy via `newgrp docker`): clone
  VonHoltenCodes/SlowBooks-Pro-2026 at the pinned tag into scratch, `docker compose up`
  with a generated `PAYROLL_ENCRYPTION_SECRET` on a free port, bootstrap through
  `POST /api/auth/setup` → `/api/auth/login` → `POST /api/api-tokens` (bookkeeper and
  readonly tokens), run each milestone's e2e block, diff live `/openapi.json` against
  the pinned snapshot, tear down with `docker compose down -v`.
- **Drift**: a unit test asserts every named command's operation exists in every
  pinned snapshot. Adding an SBP version = drop its snapshot in `testdata/`, bump
  the e2e tag, one PR.
- **Live smoke** (manual): `scripts/smoke-live.sh` on books.kodade.com (Acme demo):
  reads, then one invoice create + void.
- Tests pin facts, not status prose.

## 9. Process

- Workers: Codex `gpt-6.1-sol` medium, one T3 thread per milestone, briefed with
  `worker-brief`. Per PR: worker done-when + CI green → orchestrator full-diff read and
  accept.sh rerun → cold `reviewer` → `pr-stress` → fix rounds in the author's thread →
  `gh pr ready` → squash merge. Findings for later milestones go as comments on that
  milestone's issue.
- After M6: one `skeptic-review` on main (Omarchy Linux, Mac Studio macOS; Windows is
  CI only). Then tag `v0.1.0` with notes "verified against SlowBooks Pro 2.31.10".
- Tracking: GitHub issues are the truth; Basecamp `github` board card `slowbooks-cli`
  with one step per milestone. The orchestrator logs; workers report.
